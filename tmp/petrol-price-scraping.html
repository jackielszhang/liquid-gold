Liquid Gold data pipeline

How petrol table prices are taken and used

The app does not crawl petrol stations. It downloads the official South African fuel-price notice, pulls the coastal and inland numbers off that document, stores them as cents per litre, then uses those numbers plus a separate forecast to tell you whether to fill now or wait.

Important: this is not a web-table scraper. It does not walk HTML <table> rows. It flattens the official file into text, then hunts for labels like Petrol 95 followed by two numbers. Coastal is first. Inland is second.

The whole trip in six steps

Every daily run follows the same path. If any required price is missing, the old published file is left untouched.

1

Fetch

GitHub Actions runs update_fuel_data.py. It tries OFFICIAL_PRICES_URL.

2

Fallback

No URL, or the download fails? Use the local fixture HTML instead of crashing.

3

Extract

HTML/TXT is read as text. A PDF is stripped with pypdf. Layout is discarded.

4

Match

A regex finds fuel labels and the next two numbers: coastal, then inland.

5

Publish

Only Petrol 95 and Diesel 50ppm survive. Written to public/fuel-data.json.

6

Show

The iOS app fetches that JSON and converts cents into R/L for the widget.

Which files do the work

If a number looks wrong, start with the parser. If a number never arrived, start with the fetch.

Download

scripts/fetch_sources.py saves the file into data/raw/, or returns nothing on timeout.

Official adapter

scripts/sources/dmre.py is a thin wrapper. DMRE is the department that publishes the official schedule.

Price parser

scripts/parse_official_prices.py is the actual “table scrape”: labels, two numbers, cents.

Orchestrator

scripts/update_fuel_data.py glues fetch + parse + forecast + validation + publish.

How the table is taken

The daily job does not browse a website. It downloads one file: whatever OFFICIAL_PRICES_URL points at. HTML, TXT, or PDF all work.

Download, then keep a copy

If the env var is set, the file is saved into data/raw/. That copy is useful when a later run fails: you can still inspect what arrived.

If the env var is empty or the request times out (30 seconds), the pipeline quietly switches to data/fixtures/official-price-sample.html. That is why a fresh clone still produces a JSON file.

GitHub Actions schedules this at 06:15 UTC every day, then commits public/fuel-data.json if anything changed. You can also trigger it by hand.

What “the table” looks like today

The fixture is not a real HTML table. It is just labelled lines:

<h1>Fuel price schedule effective 2026-07-01</h1>
<p>Petrol 95 Coastal 25.23 Inland 25.87</p>
<p>Petrol 93 Coastal 25,15 Inland 25,79</p>
<p>Diesel 50ppm Coastal 23.45 Inland 24.10</p>

How those numbers are pulled out

Owner: scripts/parse_official_prices.py. The parser never cares which column a number sat in. It only cares about the words sitting in front of the numbers.

One line, scanned left to right

Take the Petrol 95 line. The regex grabs three pieces and ignores the rest.

Petrol 95 Coastal 25.23 Inland 25.87
1. Label → key petrol_95
2. First number → coastal 25.23 → 2523c
3. Second number → inland 25.87 → 2587c
label

Look for Petrol 95, 95 ULP, Petrol 93, 93 ULP, or Diesel 50 ppm. Spacing and case do not matter.

coastal

The first number after the label is coastal. Accepts 25.23, 25,23, or already-cents values like 2523.0.

inland

The second number is inland. Same formats. Then the match is stored under a fuel key.

date

A second, looser regex grabs the first date it sees, such as 2026-07-01. That becomes effective_date.

What gets kept

Label found Stored as Published?
Petrol 95 petrol_95 yes
Petrol 93 petrol_93 parsed, then dropped
Diesel 50ppm diesel_50ppm yes

SUPPORTED_FUELS in the updater is only petrol_95 and diesel_50ppm. Petrol 93 is parsed because the regex can see it, but the published contract the app reads does not include it.

Rands become cents

Apps hate floating point for money. The parser always stores integer cents.

25.23
→
× 100
→
2523

Rule: if the number is already bigger than 1000, treat it as cents and leave it. So 2523.0 stays 2523. A comma like 25,23 is treated as a decimal, not a thousands separator — unless both a comma and a dot are present, in which case the comma is stripped.

How those prices are used

Scraping is only the input. The thing the phone actually shows is a recommendation built from official prices plus a separate forecast feed (CEF), not from this table.

1. JSON contract

After validation, prices land in public/fuel-data.json. History of the last 90 successful runs is appended to public/fuel-data-history.json.

petrol_95 inland 2587c → R25.87/L

2. Recommendation

calculate_recommendation.py adds the forecast change (in cents) onto the current coastal and inland prices.

Drop of 30c or more → wait. Rise of 30c or more → fill now. Smaller move → fill normally.

3. iOS app + widget

FuelDataService fetches the GitHub JSON. Remote first, then cache, then the bundled sample.

The user picks Coastal/Inland and Petrol 95 / Diesel. PriceFormatter turns 2587 into R25.87/L.

Concrete walkthrough using the current fixture

Fuel Scraped now Forecast change Estimated next Advice
Petrol 95 inland 2587c (R25.87) −80c 2507c (R25.07) Wait if you can
Diesel 50ppm inland 2410c (R24.10) +55c 2465c (R24.65) Fill before the change

The next adjustment date is not scraped. It is calculated as the first Wednesday of next month. Tank impact is later math in the app: change_cents × tank_litres / 100. Data older than 48 hours is marked stale in the UI.

Safety nets, because scrapers lie

Official files change layout. The pipeline is designed to fail closed, not to publish garbage.

Validators

Each price must be an integer between 1000 and 5000 cents (R10–R50/L). It cannot jump more than R5.00/L or 25% from the previous publish. Petrol 95 and Diesel 50ppm both need coastal and inland.

Do not overwrite a good file

If parsing or validation fails, the script exits 1 and leaves the previous public/fuel-data.json in place. The app then keeps using cache.

Manual override

data/manual-override.json can replace prices or forecast when a real source is unreadable. Set enabled: true.

The fragile bit

If the official PDF stops putting coastal before inland, or renames “Petrol 95”, the regex will miss or swap values. That is why the README says: change the regex, or swap the DMRE adapter, when you have a stable real sample — do not pretend this layout is sacred.

Secondary source is mostly unused

SECONDARY_VALIDATION_URL is downloaded and stored as validation_url, but the AA adapter only keeps a text snippet. Price sanity checks come from validate_data.py against the previous JSON, not from that second source.
